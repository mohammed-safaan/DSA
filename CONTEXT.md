## Glossary

Core vocabulary used throughout the repo. Use these terms consistently; don't drift to synonyms.

| Term | Definition |
| ---- | ---------- |
| Big-O | Asymptotic complexity notation. Always stated as time (and space where relevant). |
| Pattern | A reusable problem-solving technique (two pointers, sliding window, …). |
| Topic | A category of solutions grouped by pattern, e.g. `two-pointers/`. |
| Solution note | The `README.md` inside each problem folder: problem link, approach, complexity, reflection. |
| Reflection | The "what I learned / where I got stuck" section of a solution note. |
| Mastery map | The topic status table in `README.md` (upcoming / in progress / practiced / mastered). |
| PRD | A learning goal document under `.scratch/<topic>/PRD.md`. |

## Conventions

- Each solved problem lives in `solutions/<topic>/<problem-slug>/` with the solution file(s) and a `README.md` solution note.
- Every solution note states Big-O time (and space when non-trivial) — never omit it.
- Keep everything in this repo honest: no inflated problem counts, no copied solutions without attribution.
- Format code with the language's standard convention (C99 style; Prettier-compatible JS).
